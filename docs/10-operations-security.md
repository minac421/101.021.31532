# 10 — التشغيل والمراقبة والأمن والاختبار

## 1. المراقبة (Observability)

| المجال | أهم المقاييس |
|---|---|
| البيانات | رسائل/ثانية لكل بث، التأخر p50/p99، الفجوات، إعادة المزامنة، التقادم لكل رمز، درجة الجودة، استهلاك وزن REST |
| الاستخبارات | زمن حساب اللقطة، نسب القيم المفقودة في الميزات، PSI للانحراف |
| القرار | المرشحون/ساعة، الأطروحات/ساعة، القرارات حسب النوع، توزيع `EV⁻`، أسباب الرفض الأكثر تكراراً، نسبة "الغموض" بين الاتجاهين |
| المخاطر | الحالة لكل نطاق، المخاطرة المفتوحة، التعرض الإجمالي والصافي، الربح والخسارة اليومي مقابل الحدود، نسبة الهامش، المسافة إلى التصفية، مرات تفعيل كل قاعدة |
| التنفيذ | زمن القرار ← الإرسال ← التنفيذ، الرفض حسب الرمز، الانزلاق مقابل النموذج، نسب التنفيذ، زمن تأكيد الوقف |
| الحساب | رأس المال، الربح المحقق وغير المحقق، التمويل، الرسوم |
| النظام | المعالج/الذاكرة/القرص، نبضات الخدمات، انحراف الساعة، حالة قواعد البيانات والناقل |

**اللوحات:** صحة البيانات؛ المخاطر والمحفظة (الأهم)؛ القرارات وخرائط السيولة للرموز المرشحة؛ جودة التنفيذ؛ أداء الإصدارات (البطل مقابل المتحدي)؛ التعلم والانحراف.

## 2. التنبيهات

| الشدة | أمثلة | القناة | زمن الاستجابة المتوقع |
|---|---|---|---|
| **P1** | مركز بلا وقف، تفعيل مفتاح الإيقاف، اختلاف مطابقة، فشل بيانات مع مراكز مفتوحة، إجراء من الحارس، حد خسارة حرج | بوت التنبيهات + اتصال/رسالة | دقائق |
| **P2** | DEGRADED لمصدر، رفض أوامر متكرر، انحراف نموذج، CAUTION/REDUCE_ONLY | بوت التنبيهات | ساعات |
| **P3** | تقارير يومية/أسبوعية، معلومات | بوت/بريد | — |

- كل تنبيه P1 مرتبط بدليل تشغيل (Runbook) يبين الخطوات الأولى.
- تنبيه "الصمت": غياب أي تقرير يومي أو نبض لخدمة مراقبة = تنبيه بحد ذاته (من يراقب المراقب؟ خدمة خارجية بسيطة تتلقى نبضاً دورياً).

## 3. التقارير

- **يومي:** الأداء، القرارات وأسباب الرفض، الحوادث، جودة البيانات، حالة المخاطر.
- **أسبوعي (مراجعة):** إسناد الأداء حسب العائلة والنظام والرمز، تصنيف أسباب الخسارة، معايرة النماذج، مقارنة البطل/المتحدي، قائمة إجراءات بحثية مقترحة — بملخص بشري القراءة.

## 4. الأمن

| المجال | الضوابط |
|---|---|
| حساب Binance | حساب فرعي مخصص يحمل رأس مال المخاطرة فقط؛ مصادقة ثنائية على الحساب الرئيسي؛ لا صلاحيات تحويل عام |
| مفاتيح API | مفتاح لكل خدمة بأقل صلاحية: المجمّعات بلا مفتاح أو بقراءة فقط؛ المتداول: تداول فقط؛ الحارس: مفتاح منفصل؛ **السحب معطّل دائماً**؛ قائمة IP بيضاء؛ تدوير كل 90 يوماً |
| الأسرار | sops + age (ثم Vault)؛ تُفك وقت التشغيل؛ لا تُسجَّل أبداً؛ لا تدخل Git |
| الخوادم | دخول SSH بالمفاتيح فقط، جدار ناري، تحديثات أمنية آلية، أقل عدد من المنافذ |
| الشبكة | اللوحات وواجهة التحكم وقواعد البيانات خلف VPN خاص — لا شيء مكشوف للإنترنت |
| واجهة التحكم | مصادقة قوية + عامل ثانٍ؛ أدوار (مشاهد/مشغّل/مسؤول)؛ إعادة مصادقة للإجراءات الخطرة؛ تدقيق كامل |
| سلسلة التوريد | اعتماديات مثبتة ببصمات، مسح الصور، مراجعة التحديثات |
| النموذج اللغوي | بلا أدوات؛ تحقق من المخطط؛ صلاحية غير متماثلة (تقليل المخاطرة فقط) |
| مفتاح توقيع سياسة المخاطر | لدى المالك البشري فقط (جهاز منفصل/مفتاح عتادي) — **لا يوجد على أي خادم** |

## 6. CI/CD وعملية الإصدار

1. كل تغيير: ruff، فحص الأنواع، اختبارات الوحدة والخصائص، `import-linter` (حدود الوحدات)، **اختبار أن مخطط المُحسِّن لا يقبل أي مفتاح مخاطر**، اختبارات الحوكمة على قاعدة بيانات مؤقتة.
2. اختبارات إعادة التشغيل الذهبية: أيام مرجعية مسجلة (منها أيام الأزمات) تُعاد عبر النظام؛ أي تغير غير مقصود في القرارات يُفشل البناء.
3. بناء صور موقّعة تُشار إليها بالـ digest.
4. حزمة الإصدار تُسجَّل كمرشح وتمر بخط الترقية ([09](09-learning-validation.md#8-خط-الترقية-والبوابات)).
5. النشر الحي يدوي بعد الموافقة، مع إمكانية التراجع بأمر واحد.

## 7. استراتيجية الاختبار

| المستوى | ماذا يختبر |
|---|---|
| الوحدة | المنطق الصافي: الميزات، الكواشف، التحجيم، التقريب لفلاتر المنصة |
| الخصائص (hypothesis) | ثوابت المخاطر I1–I10 ([07 §11](07-risk-management.md#11-ثوابت-للاختبار-الآلي-property-based-tests)) لكل المدخلات الممكنة |
| العقود | موصل المنصة مقابل رسائل مسجلة (تشمل رسائل الأخطاء وأحداث `ALGO_UPDATE`) |
| التكامل | تدفقات الأوامر كاملة على Testnet |
| التكافؤ | الحي مقابل إعادة التشغيل للميزات والقرارات |
| الفوضى (Chaos) | قطع WS، تأخير الرسائل، بيانات متقادمة، رفض أوامر، قتل العمليات، امتلاء القرص، انحراف الساعة ← التحقق من الوصول إلى حالة آمنة |
| الأداء | عاصفة رسائل (إعادة تشغيل 2025-10-10 بسرعة 5×) |
| التعافي | استعادة النسخ الاحتياطية شهرياً |

## 8. أدلة التشغيل (Runbooks) — الحد الأدنى قبل الكناري

| الحادثة | أول الخطوات |
|---|---|
| مركز بلا وقف | تأكد من إجراء الحارس؛ ضع وقفاً يدوياً من واجهة Binance عند الحاجة؛ حقق في السبب |
| انقطاع المنصة | لا محاولات متكررة؛ تحقق من الإيقافات المسجلة عند العودة؛ مطابقة كاملة قبل الاستئناف |
| انهيار الخادم الحي | الحارس يحمي؛ أعد التشغيل؛ المطابقة أولاً؛ راجع السجل |
| تسرب/اختراق مفتاح API | ألغِ المفتاح فوراً من Binance، أغلق المراكز يدوياً إن لزم، دوّر كل الأسرار، حقق |
| بوت خارج عن السيطرة | K1/K2 من اللوحة أو CLI أو البوت؛ وإن تعذر: إلغاء المفتاح من Binance |
| فساد بيانات | علّم الفترة؛ أوقف التعلم عليها؛ أعد البناء من الأرشيف الخام |
| HALTED بسبب الخسارة | مراجعة حادثة مكتوبة (ماذا حدث، هل عملت القواعد كما صُممت، ماذا نغير — دون تخفيف الحدود خلال 72 ساعة) ثم إعادة ضبط بشرية |
