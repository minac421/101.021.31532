# 00 — الرؤية والمبادئ الحاكمة وحدود المعرفة

## 1. الهدف

بناء متداول آلي على عقود Binance USDⓈ-M الدائمة يتصرف كمكتب تداول مؤسسي صغير:
يراقب السوق كاملاً، ويبني فرضيات قابلة للقياس حول السيولة وتموضع المشاركين، ولا ينفّذ إلا
عندما تكون القيمة المتوقعة بعد التكاليف موجبة بهامش أمان، ويتعلم من سجله بانضباط —
مع أولوية مطلقة لحماية رأس المال.

**تعريف النجاح (بهذا الترتيب):**

1. **لا خسارة كارثية أبداً**: لا تجاوز لحدود الخسارة المعتمدة، ولا مركز بلا وقف خسارة على المنصة، ولا تداول على بيانات معطوبة.
2. **سلوك قابل للتفسير والتدقيق**: لكل قرار سجل كامل يبيّن لماذا اتُّخذ وما البدائل التي رُفضت ولماذا.
3. **ميزة إحصائية مُثبتة خارج العينة بعد التكاليف** — أو الاعتراف بغيابها والامتناع عن التداول.
4. **تحسّن تدريجي منضبط** عبر خط ترقية صارم قابل للتراجع.

> النظام الذي لا يجد ميزة مثبتة **لا يتداول**. هذا نجاح هندسي وليس فشلاً.

## 2. ماذا تعني "عقلية المتداول المؤسسي" هندسياً

| البوت التقليدي | هذا النظام |
|---|---|
| إشارة مؤشر ← دخول | **أطروحة صفقة**: سبب + شرط إبطال + هدف + أفق زمني + تكلفة متوقعة |
| اتجاه واحد مُعدّ مسبقاً | تقييم LONG وSHORT و"عدم التداول" معاً، واختيار الأعلى قيمة متوقعة بعد خصم عدم اليقين |
| وقف خسارة بنسبة ثابتة | الإيقاف حيث تبطل الفكرة هيكلياً، وبعيداً عن تجمعات السيولة الواضحة؛ والحجم يُشتق من مسافة الإيقاف |
| يتجاهل الطرف الآخر | من المزدحم؟ من يدفع التمويل؟ أين ستُجبَر المراكز على الخروج (إيقافات/تصفيات)؟ |
| يتداول باستمرار | "لا صفقة" هو القرار الافتراضي؛ الصفقة استثناء يحتاج دليلاً |
| يقيس الربح فقط | يفصل **جودة القرار** عن **جودة النتيجة** (ربح بالحظ ≠ قرار جيد) |
| يتجاهل التكاليف | الرسوم والانزلاق والتمويل جزء من حساب القيمة المتوقعة قبل الدخول |
| "يتعلم" بتعديل المعاملات على آخر بيانات | يتعلم عبر تحقق خارج العينة ← تداول ورقي ← كناري ← موافقة بشرية |

## 3. المبادئ الحاكمة وآلية فرض كل منها

المبدأ الذي لا تفرضه آلية تقنية مجرد أمنية؛ لذلك لكل مبدأ آلية فرض محددة:

| # | المبدأ | آلية الفرض التقنية |
|---|---|---|
| P1 | حماية رأس المال قبل الربح | **Risk Guardian** يملك حق النقض (veto) على كل أمر؛ لا يوجد أي مسار تنفيذ يتجاوزه |
| P2 | **قواعد الحماية لا تتغير آلياً أبداً** | سياسة المخاطر ملف موقَّع رقمياً بمفتاح المالك البشري؛ صلاحية كتابتها لدور بشري فقط في قاعدة البيانات؛ مخطط المُحسِّن يرفض أي مفتاح مخاطر؛ اختبار CI يتحقق من ذلك؛ أي تخفيف للقيود لا يسري قبل فترة تهدئة 24 ساعة |
| P3 | الصدق المعرفي | كل استنتاج عن "الحيتان" يُسجَّل **بصمةً احتمالية** مع تفسيرات بديلة ودرجة ثقة، ولا تُستخدم إشارة في القرار قبل قياس قيمتها التنبؤية تجريبياً |
| P4 | لا مركز بلا حماية على المنصة | وقف الخسارة أمر شرطي على خادم Binance (Algo Order) يجب تأكيده خلال ثوانٍ وإلا يُغلق المركز فوراً؛ والحارس المستقل يتحقق دورياً |
| P5 | الفشل الآمن | أي عطل أو غموض في البيانات أو الحالة ← تصعيد تلقائي في آلة حالات المخاطر نحو تقليل المخاطرة؛ التخفيف لا يكون إلا بعد زوال السبب ومهلة، ومن حالتي FLATTEN/HALTED لا يكون إلا يدوياً |
| P6 | تطابق البيئات | الكود نفسه للقرار والمخاطر يعمل في Backtest وPaper وLive؛ لا يتغير إلا مصدر البيانات والساعة ومكان التنفيذ؛ اختبارات تكافؤ إلزامية |
| P7 | صحة النقطة الزمنية (Point-in-Time) | كل معلومة تحمل وقت حدوثها ووقت توفرها (`available_ts`)؛ كل ربط تاريخي يتم as-of؛ كون الرموز تاريخي بلا انحياز النجاة (يشمل الرموز المشطوبة) |
| P8 | كل شيء مسجَّل وقابل لإعادة الإنتاج | سجل أحداث إلحاقي (append-only)؛ كل قرار يحمل نسخة الكود والنماذج والإعدادات وبصمة سياسة المخاطر |
| P9 | لا ترقية دون دليل | بوابات متتالية: Backtest ← Walk-Forward/CPCV ← ضغط ← Paper ← Canary، مع مقارنة إحصائية بالنسخة الحالية |
| P10 | الإنسان صاحب القرار النهائي | الترقية إلى رأس مال حقيقي، وتغيير سياسة المخاطر، والخروج من التوقف — كلها تتطلب موافقة بشرية موثقة |
| P11 | البساطة أولاً | كل تعقيد (نموذج، ميزة، استراتيجية) يجب أن يثبت تفوقه خارج العينة على بديل أبسط |
| P12 | عزل الأعطال | عمليات منفصلة للبيانات والتحليل والقرار والتنفيذ؛ حارس مستقل على خادم منفصل وبمفتاح API منفصل |
| P13 | لا تسجيل = لا صفقة | إذا تعذّر تسجيل القرار في السجل فلا تُفتح صفقة (الإجراءات الوقائية مستثناة دائماً) |

## 4. النطاق

**داخل النطاق:**

- عقود USDⓈ-M الدائمة (`PERPETUAL`) المقوّمة بـ USDT على Binance، في حساب فرعي مخصص.
- آفاق زمنية من دقائق إلى أيام (متوسط احتفاظ متوقع: 30 دقيقة – 3 أيام).
- **مراقبة** كل الرموز النشطة، و**تداول** مجموعة مصفّاة حسب السيولة والجودة.
- بحث، اختبار رجعي، تداول ورقي، كناري، إنتاج.

**خارج النطاق (Non-goals) حالياً:**

- التداول عالي التردد وصناعة السوق والمراجحة على زمن الاستجابة: لا نملك ميزة زمنية أمام شركات HFT، ومنافستها في ملعبها خاسرة.
- المراجحة بين المنصات (قد تُدرس لاحقاً).
- السوق الفوري، الخيارات، COIN-M، والعقود الدائمة على أصول تقليدية (TradFi) — تُستبعد الأخيرة افتراضياً لاختلاف ديناميكيات أصولها وساعات تداولها.
- إدارة أموال الغير (تبعات تنظيمية).
- أي وعد بعائد.

## 5. الافتراضات (تحتاج تأكيدك)

| الافتراض | لماذا يهم | إن لم يصح |
|---|---|---|
| رأس المال صغير-متوسط مقارنة بسيولة الرموز المتداولة | أوامرنا لا تحرّك أسعار الفئتين A/B بشكل ملموس | تتغير نمذجة التنفيذ (تقسيم الأوامر، أثر السوق) |
| مشغّل بشري واحد على الأقل يستجيب للتنبيهات الحرجة | الحوكمة والتوقف يتطلبان إنساناً | يجب تشديد الحدود أكثر وتقليل الصلاحيات الآلية |
| بايثون هي لغة الفريق الأساسية | اختيار التقنيات | — |
| الاستضافة في موقع يسمح قانونياً باستخدام Binance Futures | الامتثال واستمرارية الوصول | لا يُبنى النظام قبل حل هذه النقطة |
| ميزانية البيانات المدفوعة محدودة مبدئياً | التصميم يعمل بالبيانات المجانية + التسجيل الذاتي | المدفوع (مثل تاريخ L2) يسرّع البحث ولا يغيّر البنية |

## 6. حدود المعرفة — ما الذي لا يمكن استنتاجه

| ما نراه | ما لا نستطيع استنتاجه | كيف يتعامل النظام |
|---|---|---|
| جدار أوامر كبير في الدفتر | أنه نية شراء/بيع حقيقية؛ قد يكون انتحالاً (Spoofing)، أو مخزون صانع سوق، أو تحوطاً لمركز في منصة أخرى | نقيس عمر الجدار وسلوكه عند اقتراب السعر (يُسحب؟ يُنفَّذ؟) ونعطيه "درجة احتمال انتحال"، ونسجل التفسيرات البديلة |
| صفقات تنفيذ كبيرة (Large prints) | هوية المنفّذ أو هدفه (فتح، إغلاق، تحوط، تصفية) | نصنّفها بصمة تدفق عدواني، ونربطها بتغيّر OI لتمييز الفتح من الإغلاق احتمالياً |
| تغيّر العقود المفتوحة (OI) | من فتح أيّ طرف؛ فلكل عقد مشترٍ وبائع | تحليل رباعي (اتجاه السعر × اتجاه OI) قرينةً احتمالية لا حقيقة |
| نسب Long/Short | مراكز "المال الذكي"؛ "كبار المتداولين" في Binance معرّفون بحجم الرصيد لا بالمهارة، والبيانات لـ Binance وحدها وبدقة 5 دقائق | ميزة كغيرها تُقاس قيمتها التنبؤية ولا تُفترض |
| بث التصفيات | الحجم الكلي للتصفيات؛ Binance تبث تصفية واحدة كحد أقصى لكل رمز كل 1000ms | نعامل البيانات عيّنةً وحداً أدنى، ونستخدم الشدة النسبية لا المجاميع المطلقة |
| خرائط التصفيات (Heatmaps) | مستويات التصفية الفعلية؛ هي تقديرات نموذجية (منا أو من طرف ثالث) | توسم دائماً "تقديرية" ولا تُستخدم وحدها |
| أوامر الإيقاف | لا تظهر في الدفتر إطلاقاً | "تجمعات السيولة" فرضيات عن أماكن الإيقافات المعتادة تُختبر تجريبياً |
| أوامر جليدية (Iceberg) | الحجم الحقيقي | نستدل بإعادة التعبئة المتكررة عند المستوى نفسه، وبثقة محدودة |
| تدفقات On-chain | النية؛ قد تكون نقلاً داخلياً أو حفظاً | سياق منخفض التردد، لا محفّز دخول |
| ارتباط العملة بالبيتكوين | ثباته؛ الارتباطات تنهار أو تقفز نحو 1 في الأزمات | نستخدم ارتباطاً "مُجهَداً" (stressed) في حساب المخاطر |
| أداء الاختبار الرجعي | الأداء المستقبلي | تحقق متدحرج، تصحيح لعدد التجارب (DSR)، احتمال الإفراط (PBO)، ورقي، كناري |

> **قاعدة لغوية ملزمة في السجلات والواجهات:** يكتب النظام
> «بصمة متوافقة مع تراكم شرائي (ثقة 0.42؛ تفسيرات بديلة: تغطية مراكز بيع، مخزون صانع سوق)»
> ولا يكتب أبداً «الحيتان تجمع».

## 7. معجم مختصر

| المصطلح | المعنى في هذا المشروع |
|---|---|
| أطروحة صفقة (Trade Thesis) | فرضية قابلة للاختبار: الاتجاه، الدخول، شرط الإبطال، الأهداف، الأفق، الاحتمال، التكلفة |
| بصمة (Footprint) | حدث رصدي في التدفق/الدفتر/التموضع، مع قوة وثقة وتفسيرات بديلة |
| تجمّع سيولة (Liquidity Pool) | مستوى سعري يُرجَّح تراكم أوامر إيقاف/اختراق/تصفيات حوله |
| كنس السيولة (Sweep) | اختراق قصير لتجمّع سيولة ثم عودة السعر — "صيد الإيقافات" |
| مصيدة اختراق (Breakout Trap) | اختراق يفشل ويعود داخل المستوى خلال أفق قصير |
| R | وحدة المخاطرة: الخسارة إذا ضُرب الإيقاف. ربح 2R = ضعف المخاطرة |
| EV⁻ | القيمة المتوقعة المتحفظة: محسوبة بالحد الأدنى لاحتمال النجاح بعد خصم عدم اليقين |
| Risk Guardian | وحدة المخاطر التي تقرّ أو ترفض كل أمر وتحدد حجمه النهائي |
| Watchdog | الحارس المستقل على خادم منفصل؛ لا يفتح صفقات، يحمي ويُغلق فقط |
| Champion / Challenger | النسخة المعتمدة حالياً / النسخة المرشحة التي تُقارن بها |
| Point-in-Time | استخدام المعلومة كما كانت معروفة في لحظة القرار فقط |
