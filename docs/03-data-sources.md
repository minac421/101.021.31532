# 03 — مصادر البيانات وخطة الجمع وجودة البيانات

> **حالة التحقق:** الحقائق الخاصة بواجهات Binance أدناه مراجَعة بتاريخ 2026-11-23 عبر البحث في الوثائق الرسمية ومصادر تابعة لها. لم يكن موقع `developers.binance.com` متاحاً مباشرة من بيئة التصميم، لذلك **تُعاد مطابقة كل نقطة مع الوثائق الرسمية في Spike المرحلة 0**، وتُقرأ القيم الديناميكية (حدود المعدل، الفلاتر، الرموز) من المنصة وقت التشغيل لا من ثوابت في الكود.

## 1. تغييرات جذرية حديثة في Binance يجب أن يحترمها التصميم

| التغيير | التاريخ | الأثر على التصميم |
|---|---|---|
| نقل الأوامر الشرطية (`STOP_MARKET`، `TAKE_PROFIT_MARKET`، `STOP`، `TAKE_PROFIT`، `TRAILING_STOP_MARKET`) إلى **Algo Service** عبر `POST /fapi/v1/algoOrder`؛ إرسالها عبر نقطة الأوامر العادية يُرفض | ديسمبر 2025 | أوامر وقف الخسارة تُرسل عبر Algo Order API، وتُتابع عبر حدث `ALGO_UPDATE` في User Data Stream، وتُطابق عبر نقاط استعلام أوامر Algo |
| تقسيم WebSocket إلى مسارات موجّهة: `wss://fstream.binance.com/public` (بيانات عامة عالية التردد: الدفاتر وأفضل عرض/طلب)، و`/market` (بيانات السوق المعتادة: الصفقات، سعر العلامة، الشموع…)، و`/private` (بيانات الحساب) | الروابط القديمة توقفت بعد 2026-04-23 | المجمّعات تفتح اتصالات منفصلة لكل مسار، وجدول التوجيه إعداد قابل للتحديث لا ثابت |
| تعديل وصف بث التصفيات `!forceOrder@arr` و`<symbol>@forceOrder`: يُدفع **أكبر** أمر تصفية واحد لكل رمز خلال 1000ms (بدلاً من "الأحدث") | 2026-06-20 | بيانات التصفيات عيّنة منحازة نحو الأكبر وحدّ أدنى للحجم الكلي، لا مجموع كامل |

## 2. Binance USDⓈ-M — WebSocket

**تأكيد مستقل للتوجيه:** موصل NautilusTrader 1.231.0 يرسل الدفاتر وbookTicker إلى `/public`، والصفقات وسعر العلامة والإحصاءات والشموع إلى `/market` ([SPIKE-001](spikes/SPIKE-001-trading-kernel.md)) — مطابق للجدول أدناه. ما يزال مسار `forceOrder` و`miniTicker` و`contractInfo` بحاجة إلى تحقق.

**حدود الاتصال** (حسب الوثائق الرسمية؛ تُعاد مطابقتها): حتى **200 بث لكل اتصال**، و**10 رسائل واردة في الثانية** لكل اتصال (اشتراك/إلغاء/ping)، وصلاحية الاتصال 24 ساعة.

| البث | المسار | المحتوى | الاستخدام | ملاحظات |
|---|---|---|---|---|
| `<symbol>@depth@500ms` | `/public` | تحديثات تفاضلية للدفتر | دفتر محلي لكل الرموز المؤهلة | ميزات عمق مشتقة فقط للرموز العادية |
| `<symbol>@depth@100ms` | `/public` | تحديثات تفاضلية للدفتر | دفتر عالي الدقة للمرشحين والمراكز المفتوحة | يُسجَّل خاماً |
| `<symbol>@bookTicker` | `/public` | أفضل عرض/طلب لحظياً | السبريد، التنفيذ، الانزلاق | للمرشحين والمراكز |
| `<symbol>@aggTrade` | `/market` | الصفقات المجمّعة | CVD، البصمات، بناء الشموع محلياً | لكل الرموز المؤهلة |
| `<symbol>@kline_1m` | `/market` | الشموع الرسمية | تحقق متقاطع من الشموع المبنية محلياً | — |
| `!markPrice@arr@1s` | `/market` | سعر العلامة والمؤشر ومعدل التمويل الحالي ووقت التمويل التالي لكل الرموز | التمويل، العلاوة/الأساس، حساب التصفية | بث واحد لكل السوق |
| `!forceOrder@arr` | حسب جدول التوجيه | أوامر التصفية | شدة التصفيات | **عيّنة**: حد أقصى 1 لكل رمز/ثانية |
| `!ticker@arr` / `!miniTicker@arr` | حسب جدول التوجيه | إحصاءات 24 ساعة | الماسح، التصنيف حسب السيولة | — |
| `!contractInfo` | حسب جدول التوجيه | تغييرات العقود (الحالة، الشرائح…) | تحديث الكون فوراً | — |
| User Data Stream (`listenKey`) | `/private` | `ORDER_TRADE_UPDATE`، `ACCOUNT_UPDATE`، `ALGO_UPDATE`، `MARGIN_CALL` … | حالة الحساب والأوامر والإيقافات | **أعلى أولوية؛ لا يُسقط أبداً تحت الضغط** |

**خطة الاتصالات** (N = عدد الرموز المؤهلة؛ نترك هامشاً ونستخدم ≤150 بثاً للاتصال):

| المجموعة | المسار | عدد الاتصالات التقريبي |
|---|---|---|
| `aggTrade` لكل الرموز | `/market` | ⌈N/150⌉ |
| `kline_1m` لكل الرموز | `/market` | ⌈N/150⌉ |
| المصفوفات العامة (`!markPrice@arr@1s`، `!forceOrder@arr`، `!ticker@arr`، `!contractInfo`) | حسب التوجيه | 1–2 |
| `depth@500ms` لكل الرموز | `/public` | ⌈N/150⌉ |
| `depth@100ms` + `bookTicker` للمرشحين (≤ 50 رمزاً) | `/public` | 1 |
| User Data | `/private` | 1 (للمتداول) |

- **تدوير بلا فجوات**: قبل انتهاء الـ 24 ساعة يُفتح اتصال جديد ويبدأ التخزين المؤقت، ثم يُغلق القديم بعد التداخل؛ تُزال التكرارات بمعرفات الأحداث.
- **الاشتراكات الديناميكية** (ترقية رمز إلى "مركّز") تحترم حد 10 رسائل/ثانية بطابور محدود المعدل.
- **الضغط الخلفي (Backpressure)**: طوابير محدودة؛ تحت العاصفة تُخفَّض أولاً دقة الرموز غير المركّزة، ثم يُعلَّم المصدر DEGRADED. بيانات الحساب لا تُسقط أبداً.

## 3. Binance USDⓈ-M — REST

| نقطة النهاية | البيانات | التاريخ المتاح | خطة الاستخدام |
|---|---|---|---|
| `GET /fapi/v1/exchangeInfo` | الرموز، الحالة، نوع العقد، الفلاتر (tick/step/minNotional…)، حدود المعدل | لحظي | كل 5–15 دقيقة + عند `!contractInfo`؛ تُحفظ نسخاً زمنية (SCD2) |
| `GET /fapi/v1/depth` | لقطة الدفتر (حتى 1000 مستوى) | لحظي | بدء الدفتر المحلي وإعادة مزامنته |
| `GET /fapi/v1/klines` (+ `markPriceKlines`، `indexPriceKlines`، `premiumIndexKlines`) | شموع | طويل (حتى 1500 شمعة/طلب) | ملء الفجوات والتاريخ |
| `GET /fapi/v1/aggTrades` | صفقات مجمّعة | نوافذ قصيرة لكل طلب | ملء فجوات قصيرة فقط؛ التاريخ الطويل من الأرشيف |
| `GET /fapi/v1/premiumIndex` | سعر العلامة والمؤشر والتمويل الحالي | لحظي | احتياطي لبث سعر العلامة |
| `GET /fapi/v1/fundingRate` | تاريخ التمويل المستحق | طويل | يومياً |
| `GET /fapi/v1/fundingInfo` | فترة التمويل وحدوده للرموز المعدّلة | لحظي | يومياً — **فترات التمويل تختلف بين الرموز** (ليست 8 ساعات دائماً) |
| `GET /fapi/v1/openInterest` | العقود المفتوحة الحالية | لحظي | كل 30–60 ثانية للمركّزة، كل 1–5 دقائق للبقية (ضمن ميزانية الوزن) |
| `GET /futures/data/openInterestHist` | OI تاريخي (5m فأعلى) | **آخر 30 يوماً فقط** | كل 5 دقائق للمرشحين، وأقل للبقية، + أرشفة ذاتية |
| `GET /futures/data/topLongShortAccountRatio`، `topLongShortPositionRatio`، `globalLongShortAccountRatio` | نسب Long/Short | **آخر 30 يوماً فقط** | كما سبق |
| `GET /futures/data/takerlongshortRatio` | نسبة حجم المشترين/البائعين العدوانيين | **آخر 30 يوماً فقط** | كما سبق |
| `GET /futures/data/basis` | الأساس | **آخر 30 يوماً فقط** | كما سبق |
| `GET /fapi/v1/time` | وقت الخادم | — | مراقبة انحراف الساعة |
| `GET /fapi/v1/leverageBracket` (USER_DATA) | شرائح هامش الصيانة | لحظي | يومياً — لحساب سعر التصفية وحدود الرافعة |
| `GET /fapi/v1/commissionRate` (USER_DATA) | رسومنا الفعلية (maker/taker) | لحظي | يومياً — تدخل نموذج التكلفة |
| `GET /fapi/v3/account`، `GET /fapi/v3/positionRisk`، الأوامر المفتوحة وأوامر Algo المفتوحة | حالة الحساب | لحظي | المطابقة الدورية وعند الإقلاع |

**ملاحظات تشغيلية:**

- حدود المعدل **لكل IP** وتُقرأ من مصفوفة `rateLimits` في `exchangeInfo`، ويُتتبّع الاستهلاك من رؤوس `X-MBX-USED-WEIGHT-*` و`X-MBX-ORDER-COUNT-*`. عند 429 نتراجع فوراً؛ التكرار يؤدي إلى حظر IP (418) تتصاعد مدته من دقيقتين إلى 3 أيام.
- نقاط `/futures/data/*` لها حدود معدل خاصة بها: استطلاع كل الرموز كل 5 دقائق قد يتجاوزها. لذلك: **المرشحون والمراكز كل 5 دقائق، والبقية بتردد أقل**، والتغطية التاريخية الكاملة تأتي من ملف `metrics` اليومي في الأرشيف العام (بدقة 5 دقائق).
- لا تستخدم المنظومة عدة عناوين IP للالتفاف على الحدود.

## 4. الأرشيف العام `data.binance.vision`

المسار `data/futures/um/{daily|monthly}/…` ويحتوي مجموعات منها: `aggTrades`، `trades`، `klines`، `markPriceKlines`، `indexPriceKlines`، `premiumIndexKlines`، `bookTicker`، `bookDepth`، `metrics`، و`fundingRate` (شهري).

- **`metrics`** (مؤكد): `create_time, symbol, sum_open_interest, sum_open_interest_value, count_toptrader_long_short_ratio, sum_toptrader_long_short_ratio, count_long_short_ratio, sum_taker_long_short_vol_ratio` — المصدر الوحيد المجاني لتاريخ OI ونسب L/S **لأبعد من 30 يوماً**.
- **`bookDepth`**: مخططه وتردده يُتحققان في المرحلة 0 قبل الاعتماد عليه.
- لكل ملف ملف `.CHECKSUM` (SHA256) يُتحقق منه قبل الاستيراد.
- يشمل الرموز المشطوبة ← أساس **كون رموز بلا انحياز نجاة**.
- **صحة النقطة الزمنية:** بيانات الأرشيف المنشورة لاحقاً تُعطى `available_ts` تقديرياً متحفظاً (نهاية الفترة + تأخير النشر المعتاد)، ولا تُعامل كأنها كانت متاحة لحظياً.

## 5. Binance Spot

- لكل أصل له زوج فوري: شموع 1m (تحتوي حجم المشتري العدواني) لتقريب **Spot CVD**، وصفقات مجمّعة كاملة لـ BTC وETH والأصول الرئيسية.
- الاستخدام: التمييز بين حركة يقودها الفوري (طلب حقيقي) وحركة يقودها العقد الدائم (رافعة)؛ وحساب علاوة/خصم الدائم مقابل الفوري.

## 6. المصادر الخارجية

| المصدر | البيانات | الأولوية | التكلفة (للمراجعة) | الاستخدام |
|---|---|---|---|---|
| إعلانات Binance الرسمية | إدراج، شطب، تعديل عقود، صيانة، تغيير فترات التمويل | **أساسي** | مجاني | حظر الرموز المعلن شطبها، نوافذ الصيانة |
| تقويم الماكرو (FOMC، CPI، NFP، PCE) | مواعيد معروفة مسبقاً من المصادر الرسمية | **أساسي** | مجاني | نوافذ حظر الدخول |
| Deribit (واجهة عامة) | مؤشر DVOL، التقلب الضمني، الانحراف (skew) لـ BTC/ETH | مفيد | مجاني | نظام التقلب والمخاطر |
| مجمّعات المشتقات (Coinalyze، Coinglass) | OI وتمويل وتصفيات مجمّعة عبر المنصات؛ خرائط تصفيات **تقديرية** | مفيد/اختياري | مجاني بحدود / مدفوع | تأكيد تموضع السوق الكلي (Binance ليست كل السوق) |
| Tardis.dev (أو Kaiko/CoinAPI) | تاريخ عالي الدقة للدفاتر والصفقات لعقود Binance | **مهم للبحث المبكر** | مدفوع | اختبار استراتيجيات الدفتر قبل تراكم تسجيلاتنا الذاتية |
| CoinGecko | القيمة السوقية، هيمنة BTC، فئات القطاعات | مفيد | مجاني/مدفوع | السياق والتجميع القطاعي |
| منصات أخرى (Bybit، OKX عبر CCXT)، Coinbase | تدفق ودفاتر مقارنة، علاوة Coinbase لـ BTC | اختياري (مرحلة لاحقة) | مجاني | تأكيد عبر المنصات |
| On-chain (Whale Alert، CryptoQuant، Glassnode، Arkham) | تحويلات كبيرة، تدفقات المنصات | اختياري | مدفوع غالباً | سياق منخفض التردد — لا محفّز |
| أخبار (CryptoPanic، RSS لمواقع رئيسية) | أحداث | مفيد | مجاني/مدفوع | السياق والمخاطر عبر خط الأخبار |
| أسواق تقليدية (DXY، عقود مؤشرات الأسهم) | سياق الماكرو | اختياري | متفاوت | نظام السوق العام |

> **ابدأ التسجيل من اليوم الأول.** تاريخ الدفاتر غير متاح من Binance إطلاقاً، وتاريخ OI ونسب L/S عبر REST لا يتجاوز 30 يوماً. كل يوم تأخير في تشغيل المجمّعات بيانات ضائعة لا تُستعاد إلا بالشراء.

## 7. بناء الدفتر المحلي (الإجراء الرسمي)

1. فتح بث `depth` وتخزين الأحداث مؤقتاً.
2. جلب لقطة `GET /fapi/v1/depth?limit=1000`.
3. إسقاط الأحداث المخزنة ذات `u` < `lastUpdateId`.
4. أول حدث يُطبَّق يجب أن يحقق `U <= lastUpdateId <= u`.
5. كل حدث تالٍ يجب أن يحقق `pu` = `u` للحدث السابق؛ وإلا ← **إعادة مزامنة** من الخطوة 1 وتعليم الدفتر "غير صالح".
6. الكمية 0 تعني حذف المستوى.
7. تحقق دوري مقارنة بلقطة جديدة (عيّنات)، وكشف الدفتر المتقاطع (best bid ≥ best ask).

> اللقطة تغطي 1000 مستوى فقط؛ ما بعدها مجهول. تُعلَّم مقاييس العمق البعيد "جزئية".

## 8. الطوابع الزمنية وصحة النقطة الزمنية

| الحقل | المعنى |
|---|---|
| `event_ts` | وقت الحدث لدى المنصة (`E`) |
| `txn_ts` | وقت المعاملة/التنفيذ لدى المنصة (`T`) |
| `recv_ts` | وقت الاستلام المحلي (ساعة حائط، ميكروثانية) + `recv_mono_ns` (ساعة رتيبة) |
| `available_ts` | **أول لحظة كان يمكن فيها استخدام المعلومة في قرار**؛ لبيانات REST = وقت الاستجابة، لإحصاءات 5m = وقت جلبها لا نهاية الفترة، لبيانات الأرشيف = تقدير متحفظ |
| `ingest_ts` | وقت الكتابة في المخزن |

**القاعدة:** الاختبارات الرجعية وبناء مجموعات التدريب تستخدم ربطاً as-of على `available_ts ≤ decision_ts` حصراً.

## 9. مراقبة جودة البيانات وحيويتها

| الفحص | الطريقة | العتبة الأولية (تُعاير) | الأثر |
|---|---|---|---|
| التقادم | عمر آخر رسالة مقابل المعدل المتوقع للرمز | > 5× متوسط الفاصل أو > 5s للمركّزة / 30s للبقية | DEGRADED للرمز |
| فجوات التسلسل | `pu`/`u` في الدفتر، معرفات الصفقات | أي فجوة | الدفتر غير صالح حتى المزامنة |
| التأخر | `recv_ts − event_ts` | p99 > 1000ms | DEGRADED |
| انحراف الساعة | chrony + `GET /fapi/v1/time` | > 250ms تحذير، > 1000ms | REDUCE_ONLY |
| الاتساق المتقاطع | آخر صفقة مقابل منتصف الدفتر مقابل سعر العلامة | انحراف > k×σ | تعليم tick شاذ |
| مطابقة الشموع | الشموع المحلية مقابل `kline` الرسمية | فرق حجم > 0.5% | تحقيق |
| الاكتمال | الرسائل/الدقيقة مقابل المتوقع | < 99% | تقرير يومي |
| صحة REST | معدل الأخطاء، 429/418، زمن الاستجابة | ارتفاع غير طبيعي | خفض الاستطلاع، تنبيه |
| حداثة التمويل/OI | عمر آخر قيمة | > فترتين | الميزة "غير متاحة" |
| إعادة المزامنة المتكررة | عدد مرات إعادة بناء الدفتر | > 3 خلال 10 دقائق | الرمز REDUCE_ONLY |

تتجمّع الفحوص في درجة جودة (0–1) لكل مصدر ورمز، وحالة `OK/DEGRADED/FAILED` تُغذّي آلة حالات المخاطر مباشرة (انظر [07](07-risk-management.md#7-مصفوفة-الاستجابة-لأعطال-البيانات-والبنية)).
