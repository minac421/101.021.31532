# 11 — خارطة الطريق ومعايير الانتقال

**مبدأ التسلسل:** البيانات والمخاطر قبل "الذكاء"، والذكاء قبل رأس المال. لا تبدأ مرحلة قبل تحقق معايير خروج سابقتها. المدد تقديرية لمطوّر متمرس واحد بدوام كامل، وتتقلص مع فريق أكبر.

| المرحلة | الهدف | أهم المخرجات | معايير الخروج | المدة التقديرية |
|---|---|---|---|---|
| **0. الأسس + Spike** | إثبات صلاحية القرارات المعمارية | المستودع، CI، docker compose، الأسرار، **Spike نواة التداول**، **مطابقة واجهات Binance مع الوثائق الرسمية** | تقرير Spike مكتوب بقرار (اعتماد/رفض)؛ CI أخضر؛ تطبيق المخططات واختبارات الحوكمة آلياً | 2–3 أسابيع |
| **1. منصة البيانات** | تسجيل كامل وموثوق **في أبكر وقت** | المجمّعات المجزأة، باني الدفاتر، مراقب الجودة، ClickHouse، الأرشيف الخام، ملء التاريخ من `data.binance.vision`، لوحة صحة البيانات | ≥ 14 يوماً متواصلة باكتمال ≥ 99.5% والفجوات موثقة؛ جداول Point-in-Time؛ قياس الأحجام الفعلية | 4–6 أسابيع |
| **2. الاستخبارات والبحث** | ميزات وكواشف بقيمة **مُثبتة** | محرك الميزات (لحظي = دفعي)، المحللات، دراسات أحداث لكل كاشف بنتائج صادقة (بما فيها السلبية) | اختبارات تكافؤ ناجحة؛ تقرير بحثي لكل كاشف: مقبول/مرفوض ولماذا | 6–8 أسابيع |
| **3. المحاكاة والتحقق** | اختبار رجعي يمكن الوثوق به | محرك الاختبار الرجعي بالنواة، نماذج التكلفة والتنفيذ، أدوات WF/CPCV/DSR/PBO، إعدادات أساسية بسيطة وشفافة لاختبار البنية | نتائج قابلة لإعادة الإنتاج بالبت؛ تكافؤ الاختبار الرجعي مع إعادة التشغيل | 4–6 أسابيع |
| **4. المخاطر والتنفيذ والورقي** | أمان التشغيل قبل أي ربح | Risk Guardian، آلة الحالات، مفتاح الإيقاف، الحارس المستقل، التنفيذ وAlgo Orders، المطابقة، السجل، واجهة التحكم، التنبيهات، **تشغيل ورقي** | ≥ 4 أسابيع ورقي: صفر مراكز بلا حماية، صفر أخطاء مطابقة غير مفسرة؛ نجاح كل اختبارات الفوضى؛ أدلة التشغيل جاهزة | 6–8 أسابيع |
| **5. محرك القرار والتعلم** | أول إصدار مرشح حقيقي | Meta-models، مصنّف المصائد، المقارنة بين الاتجاهين، الاختيار على مستوى المحفظة، التشريح، التوسيم الشامل، خط الترقية | إصدار يجتاز البوابات 1–4 مقارنة بخط أساس بسيط | 8–12 أسبوعاً |
| **6. الكناري** | التحقق برأس مال حقيقي صغير | تشغيل حي بنسبة 25% من المخاطرة العادية | البوابة 5 + موافقة بشرية | 4–8 أسابيع |
| **7. التحسين المستمر** | تطور منضبط | أتمتة المُحسِّن والبطل/المتحدي، عائلات جديدة، بيانات عبر المنصات | — | مستمر |

> **إجمالي تقديري حتى الكناري: 9–12 شهراً.** أي جدول أسرع يعني غالباً التضحية بالتحقق — وهذا تحديداً ما يُفقد الأموال.

## 1. ابدأ التسجيل فوراً

بيانات الدفاتر غير متاحة تاريخياً من Binance، وتاريخ OI ونسب L/S عبر REST لا يتجاوز 30 يوماً. لذلك تبدأ **نسخة دنيا من المجمّعات** (صفقات + دفاتر للرموز الرئيسية + إحصاءات 5m + سعر العلامة + التصفيات) في الأسبوع الأول من المرحلة 0، قبل اكتمال أي شيء آخر.

## 2. معايير قبول Spike نواة التداول (المرحلة 0)

| المعيار | الاختبار |
|---|---|
| مسارات WebSocket الموجّهة (`/public`، `/market`، `/private`) | اشتراك ناجح في الدفاتر والصفقات وUser Data |
| أوامر الوقف عبر Algo Order API وأحداث `ALGO_UPDATE` | دورة كاملة على Testnet: وضع، تفعيل، إلغاء |
| المطابقة عند الإقلاع | مراكز وأوامر Algo موجودة مسبقاً تُكتشف صحيحاً |
| البيانات المخصصة (OI، نسب L/S، اللقطات) | تُستهلك في الاستراتيجية حياً وفي الاختبار الرجعي بالطريقة نفسها |
| الاختبار الرجعي على بيانات L2 مسجلة | نتائج حتمية قابلة لإعادة الإنتاج |
| الوضع الورقي على بيانات حية | يعمل بالكود نفسه |
| فصل المنطق عن الإطار | المكتبات المستقلة تعمل خلف محولات رقيقة |

الفشل في بند حرج ← خطة بديلة: نواة خاصة بالواجهات نفسها (تزيد المرحلة 3–4 بعدة أسابيع).

## 3. قائمة الجاهزية قبل أي رأس مال حقيقي

- [ ] سياسة المخاطر النهائية موقّعة من المالك وبقيم يحددها هو.
- [ ] الحساب الفرعي مهيأ (اتجاه واحد، هامش معزول، رافعة محدودة، السحب معطّل، قائمة IP).
- [ ] ≥ 4 أسابيع ورقية بلا أي مركز غير محمي ولا أخطاء مطابقة غير مفسرة.
- [ ] الحارس المستقل يعمل على خادم منفصل، ومُختبر بقتل المتداول أثناء وجود مراكز.
- [ ] كل اختبارات الفوضى ناجحة؛ أدلة التشغيل مكتوبة ومجرّبة.
- [ ] مفتاح الإيقاف مُجرّب عبر كل القنوات.
- [ ] الإصدار اجتاز البوابات 1–4 مقارنة بخط أساس.
- [ ] النسخ الاحتياطي واستعادته مُجرّبان.
- [ ] موافقة بشرية موثقة على الكناري.

| الخطر | الاحتمال | الأثر | التخفيف |

## 5. قرارات مطلوبة منك قبل المرحلة 0

1. **رأس المال وتحمّل المخاطرة** ← تحديد القيم النهائية في سياسة المخاطر (المقترحات الحالية متحفظة).
2. **الأفق الزمني المفضل** (داخل اليوم أم عدة أيام) ← يؤثر على أولوية عائلات الإعداد وكثافة بيانات الدفاتر.
3. **ميزانية البيانات المدفوعة** (مثل تاريخ L2 من Tardis، مجمّعات المشتقات) ← تسرّع المرحلة 2–3 كثيراً.
4. **موقع الاستضافة والولاية القضائية** ← الامتثال والكمون.
5. **اعتماد نواة NautilusTrader** (موصى به، مشروط بنجاح الـ Spike) أم نواة خاصة.
6. **من يوافق على الترقيات وتغييرات المخاطر**، وكيف يُستدعى عند تنبيهات P1.
