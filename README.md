# AI Whale Trader — متداول آلي بعقلية مؤسسية على Binance USDⓈ-M Futures

> **الحالة: مرحلة التصميم المعماري (v0.1) — لا يوجد كود تداول بعد.**
> هذه الوثائق هي العقد الهندسي الذي سيُبنى عليه النظام، وتُراجَع وتُعتمد قبل كتابة أي منطق تداول.

## الفكرة

متداول آلي لا يعتمد على إشارات ومؤشرات جاهزة، بل يفكر كمكتب تداول مؤسسي: أين السيولة؟ من المزدحم؟
أين ستُجبَر المراكز على الخروج؟ يبني **أطروحات قابلة للاختبار** لكلا الاتجاهين، ويقارن LONG وSHORT
و"عدم التداول" بقيمة متوقعة متحفظة بعد التكاليف، ويتعلم من كل قرار مسجَّل —
**لكنه لا يملك أبداً صلاحية تغيير قواعد حماية رأس المال**، ويتوقف تلقائياً عند تعطل البيانات أو ارتفاع المخاطر.

**ترتيب الأولويات:** البقاء (حماية رأس المال) ← سلامة التشغيل والبيانات ← صحة القياس والتحقق ← الربح.

## أهم القرارات المعمارية

1. **ستة مستويات بصلاحيات أحادية الاتجاه:** البيانات ← التحليل ← القرار ← المخاطر ← التنفيذ؛ الذكاء لا يتجاوز المخاطر، والتعلم معزول عن التشغيل الحي.
2. **Risk Guardian بحق النقض** على كل أمر، وسياسة مخاطر **موقّعة بشرياً** لا يستطيع أي مكوّن آلي كتابتها — مفروض بالتوقيع وأدوار قاعدة البيانات وCI.
3. **وقف خسارة على خادم Binance** (Algo Order API) لكل مركز خلال ثوانٍ وإلا خروج فوري؛ **حارس مستقل** على خادم آخر.
4. **آلة حالات مخاطر** تصعّد تلقائياً عند أي عطل بيانات أو خطر، ولا تخرج من التوقف إلا بإنسان.
5. **صدق معرفي:** "بصمات" احتمالية بتفسيرات بديلة، لا "نوايا حيتان"؛ ولا يُستخدم أي كاشف قبل إثبات قيمته خارج العينة.
6. **القرار على القيمة المتوقعة المتحفظة** (`EV⁻`) بعد التكاليف وعدم اليقين، و"عدم التداول" هو الافتراضي.
7. **الكود نفسه** في Backtest وPaper وLive (نواة NautilusTrader مشروطة بـ Spike)، وصحة النقطة الزمنية في كل البيانات.
8. **خط ترقية بخمس بوابات** (Backtest ← WF/CPCV ← ضغط ← ورقي ← كناري) مع مقارنة إحصائية بالنسخة الحالية، وإصدارات غير قابلة للتعديل قابلة للتراجع بأمر واحد.
